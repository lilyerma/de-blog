    Семинар про SQLServer и Postgress

    Краткое содержание вебинара Брента Озара (Brent Ozar) «How to Think Like the Engine: SQL Server & PostgreSQL Edition»:

    🔗 Ссылка на видео: YouTube

    🎯 Главная цель занятия

    Разобраться на фундаментальном уровне, как СУБД хранят данные на диске, читают планы запросов и как индексы влияют на производительность. Основной фокус — сравнение двух движков: Microsoft SQL Server и PostgreSQL, на примере демо-базы данных Stack Overflow (порядка 300 000+ страниц на таблицу users).

    🔑 Ключевые темы и выводы:

    1. Базовая единица работы — 8K страницы (8K Pages):
    2. И в SQL Server, и в PostgreSQL данные хранятся и читаются с диска (и в памяти) страницами размером по 8 КБ. Это минимальный объем ввода-вывода (I/O).

    3. Большие типы данных (JSON, varchar(max), XML) не помещаются целиком на страницу и выносятся наружу («off-row data» с указателями).

    4. Как СУБД хранят таблицы (Главное отличие):

    5. SQL Server (Clustered Index): Таблица по умолчанию отсортирована и хранится на диске по первичному ключу (кластеризованный индекс).

    6. PostgreSQL (Heap): Сама таблица хранится в виде неупорядоченной кучи (heap). Строки идентифицируются специальным системным идентификатором CTID (номер страницы + номер слота/кортежа). Первичные и остальные индексы в Postgres всегда некластеризованные.

    7. Чтение данных и логические чтения:

    8. Без индексов поиск по строкам превращается в полный сканировчный проход по всей таблице (Scan), заставляя движок вычитывать сотен тысяч 8K-страниц.

    9. Производительность запросов лучше всего измерять по логическим чтениям (logical reads / buffers), так как физическое кеширование в памяти постоянно меняется.

    10. Индексы и B-Tree:

    11. Индексы хранятся на таких же 8K страницах, но содержат только отсортированные ключевые колонки и указатели (ID в SQL Server или CTID в PostgreSQL).

    12. Первая колонка в индексе определяет, куда движок может сделать быстрый прыжок (Seek), поэтому порядок колонок в составных индексах критически важен.

    13. Оркестрация изменений (UPDATES, INSERTS) и конкурентность:

    14. SQL Server обновляет данные «на месте» (in-place) на странице. При нехватке места происходит расщепление страниц (page split).

    15. PostgreSQL при обновлении строки создает ее новую версию в другом месте той же или соседней страницы (реализация MVCC). Это избавляет от блокировок читателей писателями, но порождает необходимость фоновой очистки — Vacuum.

    16. Философия разработки и экосистема:

    17. SQL Server: Продукт одной компании. Всё «из коробки» (индексы, подсказки optimizer hints, встроенные планы, инструменты мониторинга).
    18. PostgreSQL: Open-source сообщество с минималистичным ядром (core). Функциональность расширяется за счет тысяч сторонних плагинов и расширений (extensions). Исторически компиляция под капотом и тюнинг параметров доверяются гибкости инфраструктуры (часто проще масштабировать железо, чем переписывать сложные планы).
