    Паттерн Gaps & Islands (Непрерывные серии): как находить стрики и периоды активности в SQL

    Источник и больше задач

    Нужно найти пользователей, которые заходили в приложение 3 дня подряд и более, или выделить непрерывные интервалы, когда сервер работал без сбоев. В мире SQL эта задача решается с помощью знаменитого паттерна Gaps & Islands («Пропуски и Острова»).

    В этой статье мы разберем суть проблемы и элегантный трюк с разницей функции ROW_NUMBER(), который позволяет решить ее в один запрос.

    Суть проблемы и ментальная модель

    Представьте временную шкалу. Если пользователь заходил в систему каждый день без пропусков, даты идут плотной «цепочкой». Если между входами был перерыв в несколько дней, цепочка разрывается.

    • Острова (Islands): Непрерывные блоки дней, когда активность происходила подряд.
    • Пропуски (Gaps): Дни или периоды отсутствия активности, которые разрывают «острова».

    Наша цель — превратить каждую непрерывную серию в отдельную сущность, сгруппировать их и измерить их длину.

    Магический метод: Разница через ROW_NUMBER()

    Самый изящный способ найти «острова» — использовать оконную функцию ROW_NUMBER().

    Интуиция метода проста: если даты увеличиваются ровно на 1 день каждый раз, когда порядковый номер (ROW_NUMBER) тоже увеличивается на 1, то их математическая разница остается абсолютно константной! Как только происходит разрыв (пропуск), разница смещается и образует новый «остров».

    Давайте разберем готовый SQL-запрос для PostgreSQL:

    WITH ordered_logins AS (
  -- Шаг 1: Убираем дубли, оставляя уникальные даты входов для каждого пользователя
  SELECT DISTINCT 
    user_id, 
    CAST(login_time AS DATE) AS login_date
  FROM user_logins
),
numbered_logins AS (
  -- Шаг 2: Вычитаем ROW_NUMBER() из даты, чтобы создать уникальный ключ «острова»
  SELECT 
    user_id,
    login_date,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn,
    login_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) * INTERVAL '1 DAY') AS island_id
  FROM ordered_logins
)
-- Шаг 3: Группируем по пользователю и ключу острова, вычисляя длину стрика
SELECT 
  user_id,
  MIN(login_date) AS streak_start,
  MAX(login_date) AS streak_end,
  COUNT(*) AS consecutive_days
FROM numbered_logins
GROUP BY user_id, island_id
HAVING COUNT(*) >= 3
ORDER BY user_id, streak_start;

    Разбор шагов алгоритма под капотом

    1. Шаг 1 (ordered_logins): Мы нормализуем данные. Если пользователь заходил по 5 раз на дню, DISTINCT схлопнет это до одной уникальной даты на пользователя.
    2. Шаг 2 (numbered_logins): Здесь происходит магия. Функция ROW_NUMBER() выдает последовательные числа (1, 2, 3, 4...). Вычитая их из даты login_date, мы получаем сдвиг:
    3. Дата 2026-06-01 минус 1 день = 2026-05-31
    4. Дата 2026-06-02 минус 2 дня = 2026-05-31
    5. Дата 2026-06-03 минус 3 дня = 2026-05-31
    6. Обратите внимание: результат 2026-05-31 везде одинаков! Это и есть наш island_id.
    7. Если следующий вход произойдет только 5 июня (2026-06-05), то для него ROW_NUMBER будет равен 4. Дата 2026-06-05 минус 4 дня = 2026-06-01. Ключ изменился, значит, начался новый «остров»!
    8. Шаг 3 (Фильтрация и агрегация): Группируя по user_id и island_id, мы собираем всю серию воедино, находим ее начало (MIN), конец (MAX) и общую длину через COUNT(*) >= 3.

    Заключение

    Паттерн Gaps & Islands с использованием ROW_NUMBER() — это мощный инструмент в арсенале разработчика и аналитика данных. Он избавляет от громоздких циклов на бэкенде и позволяет решать сложные задачи временных рядов (стрики, аптаймы, непрерывные подписки) прямо на уровне базы данных за один эффективный проход.
